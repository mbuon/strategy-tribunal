## Implement the decision protocol

Use an explicit state machine. Document the entry condition, validated output, authorised role, budget charge, failure transition, and exit condition for each phase. Only the controller can commit updates or advance state. Model roles can propose changes through validated records.

1. **Frame the decision.** Identify the decision, objectives, beneficiaries or stakeholders, hard constraints, preferences, time horizon, stakes, reversibility, and evidence gaps. Preserve the user’s stated requirements and label inferred assumptions. For a broad topic, identify the concrete decision it implies. If plausible interpretations lead to different actions, evaluate them as scenarios or return a conditional finding. Once a run starts, resolve ambiguity within the workflow.
2. **Register the evaluation policy and round-zero baseline.** Define the hard gates, criteria, score anchors, weights, priority scenarios, and promotion threshold before ranking. Include the status quo or a direct initial answer where applicable. Record how the baseline was generated, the resources used, and any missing inputs.
3. **Generate diverse strategies.** Select reasoning methods based on stakes, uncertainty, reversibility, and likely blind spots. Use materially different methods, such as decomposition, inversion, analogy, dependency analysis, or an outside-view comparison. Where relevant, include the status quo, a staged commitment, and a targeted information-gathering option. Collect initial outputs before cross-review. Merge duplicates with their lineage intact. Preserve strategically distinct options that could win under plausible assumptions.
4. **Cross-review and verify.** With independently scoped model sessions, review pseudonymised options and withhold authorship and prior rankings from the review payload where possible. In shared-context mode, use the same review rubric and staged assessment, with no claim of blind review. For each material challenge, identify the target option version or claim, the failure mechanism, severity, supporting evidence, and what would resolve it. Classify disagreements as factual, evidentiary, value-based, scenario-dependent, or execution-related. Prioritise objections that could change eligibility, ranking, or the action taken. Accept compact rebuttals, verify evidence through available sources when needed, and record when verification is unavailable.
5. **Revise and adjudicate.** Allow revisions, mergers, withdrawals, and reinstatements with explicit reasons. Judge the new versions alongside the incumbent using the same evaluation policy. Send unresolved issues into targeted follow-up loops. Give a material reframe its own brief version and rerun affected evaluations. Cap both reframes and follow-up work.
6. **Challenge the leader.** Before finalisation, assign a dedicated sceptical pass to identify the strongest plausible case against the current leader. Require a scenario in which it loses, the strongest alternative in that scenario, and evidence that would distinguish them. Record the response and reopen deliberation when the challenge could alter the outcome and budget remains. If no leader exists, stress-test the shortlist or the proposed decision to defer.
7. **Stop and report.** Use an outer strategy loop, a bounded inner challenge-and-response loop, and a verification loop for decisive uncertainty or unstable rulings. Define minimum and maximum rounds and preserve a finalisation reserve. Stop for meaningful ranking stability, lack of a productive follow-up, a budget limit, cancellation, or failure. Record the exact reason and any unfinished checks. Support a firm recommendation, conditional recommendation, unresolved shortlist, targeted information request, and no eligible option.

## Make the global judge comparable across rounds

- **Register a scoring contract.** Define gate outcomes (`pass`, `fail`, `unverified`), criterion score anchors, weight normalisation, score ranges, the aggregation formula, and how missing data affects the result. Each judgement must cite evidence or state its assumptions. A failed gate disqualifies an option. An unverified gate must receive the configured treatment and remain visible.
- **Measure improvement on matched inputs.** For every promotion decision, compare the challenger and prior incumbent using the same brief, rubric, evidence snapshot, and judge configuration. Show the option’s change from its parent, the round winner’s change from the prior incumbent, and net change from round zero. If evidence, rubric, or judge configuration changes, rescore both options where feasible. If comparability cannot be restored, label the change as non-comparable and preserve the earlier result.
- **Separate improvement from uncertainty.** Set a minimum meaningful score difference and a rule for uncertainty before the first ranking. A default rule may use conservative score bounds and promote only when the challenger’s lower bound exceeds the incumbent’s upper bound by the defined margin. Specify how bounds are derived and label heuristics accordingly. Record ties, losses, and inconclusive results. Retain the incumbent unless it becomes ineligible or the challenger clears the promotion rule.
- **Control judging bias.** Score individual attributes before the overall verdict. Withhold authorship and prior rankings only when the runtime enforces a separate review context. Counterbalance candidate order in close comparisons. Define how to resolve or report judge disagreement, cyclic pairwise preferences, and gaps in evidence. Where supported, use log-probability scoring as an optional verifier signal and identify the method used. Provide a structured scoring fallback.
- **Test the action under plausible changes.** Vary influential assumptions, scenario outcomes, and criterion weights. Identify ranking flips and the evidence that would settle the most important uncertainty. Report evidence quality, judge agreement, ranking robustness, and confidence in the recommended action as separate signals. State what would raise or lower confidence and what the council failed to establish.
- **Make stopping testable.** Define how many consecutive comparable rounds with gains below the materiality threshold count as stable. Check that no unresolved objection with a credible path to changing the decision warrants further work. A budget-limited run may end earlier and must show that it did. Provide worked examples of a genuine promotion, apparent improvement caused by new evidence, and an inconclusive comparison.
